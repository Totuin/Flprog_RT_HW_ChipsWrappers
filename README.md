# FLProg_RT_HW_ChipsWrappers — версия 1.0.1

Набор адаптеров электронных компонентов для FLProg/Arduino. Исходники организованы по интерфейсам:

- `src/I2C` — ADS1115, AHTxx, BH1750, BME280, BMP180, BMP280, HTU21, MCP23017, MCP4725, PCF8574, PCF8575, SHT3x, TCA8418, TCA9555.
- `src/Pin` — DHT22, DS18x2x, HC-SR05, TM1637.
- `src/SPI_SPN` — 74HC165, 74HC595, MAX31865, MAX6675.
- `src/flprog*.h` — публичные заголовки для подключения устройств.
- `examples` — примеры использования.
- `extras/host-tests` — автономные тесты исправленных алгоритмов на заглушках RT_HW, без аппаратуры.

## Как использовать

Распакуйте каталог библиотеки целиком в `sketchbook/libraries/`. В программе/скетче подключайте соответствующий заголовок, например `#include <flprogDS18x2x.h>`. Не смешивайте файлы из разных версий внутри одной папки.

Для сборки нужны совместимые версии `Flprog_Utilites` и драйверов `RT_HW`; их исходники в архив не включены. Для корректной работы большинство устройств требует регулярного вызова `pool()` из главного цикла программы.

## Принцип документирования

В заголовках `*.h` описаны назначение классов и публичные методы. В `*.cpp` комментарии `@brief` поясняют алгоритмы и жизненный цикл; у сложной логики есть локальные комментарии о проверках и ограничениях. Прежние имена публичных методов намеренно сохранены для совместимости (в том числе исторические опечатки, такие как `getChanel*` и `resetIntrruptMode`).

## Важные ограничения

- **MAX31865 — намеренная заготовка**, оставленная разработчиком до появления драйвера RT_HW. Температура возвращается как `0.0`, `getOk()` как `true`; аппаратного обмена пока нет. Это не ошибка и не рабочее измерение.
- На `TM1637`, `TCA8418`, `TCA9555` методы `getOk()` также возвращают постоянное `true`, а не реальную диагностику физического устройства.
- `FLProgDs18x2x::pool(uint16_t useBus)` возвращает состояние занятости общей 1-Wire шины; обычный `pool()` из базового класса теперь не скрыт, но это другой метод.
- Обработчик `TCA8418::interruptReadData()` вызывает I2C: его нельзя исполнять непосредственно внутри аппаратного обработчика прерывания MCU.

Изменения перечислены в `CHANGELOG_FLPROG.md`, выявленные ограничения и границы тестирования — в `AUDIT_FLPROG.md`.
